# RAGAS Evaluation Guide

Step-by-step guide to evaluate the RAG Chat Assistant using RAGAS metrics.
To be Done in the MCP_SERVER Virtual environment. (.mcpvenv)


---

## Overview

The evaluation pipeline measures how well the RAG system retrieves and generates answers against ground-truth data. It scores each question on 4 metrics:

| Metric | What it measures | Score |
|--------|-----------------|-------|
| **Faithfulness** | Is the answer supported by the retrieved contexts? (no hallucination) | 0.0 – 5.0 |
| **Answer Relevancy** | Does the answer directly address the question asked? | 0.0 – 5.0 |
| **Context Precision** | Are the retrieved contexts relevant to the question? | 0.0 – 5.0 |
| **Context Recall** | Do the contexts cover all info needed for the reference answer? | 0.0 – 5.0 |

---

## Prerequisites

- Python virtual environment `.mcpvenv` activated
- Ollama running with the configured chat model (`gpt-oss:120b-cloud`)
- Ollama running with the embedding model (`nomic-embed-text`)
- Documents placed in `MCP_Stack/knowledge_source/`

---

## Step 1: Generate Ground-Truth Data

Ground-truth files contain question-answer-context pairs generated from your source documents. These serve as the "expected correct answers" for evaluation.

The number of Q&A pairs per document is controlled by config settings:
- `GROUND_TRUTH_MIN_QUESTIONS = 3` (minimum pairs per doc)
- `GROUND_TRUTH_MAX_QUESTIONS = 10` (maximum pairs per doc)

The actual count depends on how many sections the document has, clamped between min and max.

### Generate for all documents:

```powershell
python generate_ground_truth.py --all
```

### Generate for a single document:

```powershell
python generate_ground_truth.py "Legacy docs\XLUTS1_documentation_v17.docx"
```
# Note - ground truth Q&A's are generated by LLM, and so may have inaccuracies.
Review them against the specific docuemnts, an update as required before running the RAGAS evaluations.


### List available documents:

## Step 2: Ingest Documents into Knowledge Base

The MCP server must run at least once to ingest documents into ChromaDB + BM25 index.

```powershell
python -m MCP_Stack.mcp_server
```

Wait for ingestion to complete (you'll see progress messages). Then you can stop the server (Ctrl+C) — the knowledge base is persisted to disk.

> **Note:** The eval script reads directly from the persisted knowledge base. The MCP server does NOT need to be running during evaluation.

---

## Step 3: Run RAGAS Evaluation

### Evaluate all ground-truth files:

```powershell
python run_ragas_eval.py
```

Output file: `MCP_Stack/ground_truth_docs/eval_results_all_<timestamp>.json`

### Evaluate a specific document:

```powershell
python run_ragas_eval.py "HA_BRD_test_ground_truth.json"
python run_ragas_eval.py "XLUTS1_documentation_v17_ground_truth.json"
python run_ragas_eval.py "HA_Scoring_ground_truth.json"
```

Output file: `MCP_Stack/ground_truth_docs/eval_results_<docname>_<timestamp>.json`

## Configuration

All settings are in `MCP_Stack/config.py`:

```python
# Must be True to compute evaluation scores
ENABLE_RAGAS_EVAL = True

# Ground-truth generation limits (Q&A pairs per document)
GROUND_TRUTH_MIN_QUESTIONS = 3   # Minimum
GROUND_TRUTH_MAX_QUESTIONS = 10  # Maximum
```

Key parameters that affect evaluation quality:

| Parameter | Location | Effect on eval |
|-----------|----------|---------------|
| `RETRIEVAL_TOP_K` | `MCP_Stack/config.py` | More chunks = better recall, possibly worse precision |
| `SEMANTIC_WEIGHT` | `MCP_Stack/config.py` | Balance between semantic and keyword matching |
| `CHUNK_SIZE` | `MCP_Stack/config.py` | Larger chunks = more context per result |
| `DEFAULT_MODEL` | `MCP_Stack/config.py` | Better model = better answer generation + evaluation |
| `GROUND_TRUTH_MIN_QUESTIONS` | `MCP_Stack/config.py` | Minimum Q&A pairs generated per doc |
| `GROUND_TRUTH_MAX_QUESTIONS` | `MCP_Stack/config.py` | Maximum Q&A pairs generated per doc |

---

## Improving Scores

| Low score | Likely cause | Fix |
|-----------|-------------|-----|
| Low Faithfulness | Answer contains info not in contexts | Lower TEMPERATURE, improve prompt |
| Low Answer Relevancy | Answer doesn't address the question | Improve RAG prompt template |
| Low Context Precision | Irrelevant chunks retrieved | Tune SEMANTIC_WEIGHT, increase CHUNK_SIZE |
| Low Context Recall | Missing relevant info in retrieval | Increase RETRIEVAL_TOP_K, decrease CHUNK_SIZE |

## Complete Workflow (Quick Reference)

```powershell
# 1. Activate environment
.mcpvenv\Scripts\activate

# 2. Generate ground-truth (requires Ollama running)
python generate_ground_truth.py --all

# 3. Ingest documents (run MCP server once)
python -m MCP_Stack.mcp_server
# Wait for ingestion, then Ctrl+C

# 4. Run evaluation (all docs)
python run_ragas_eval.py

# 5. Run evaluation (single doc)
python run_ragas_eval.py "HA_BRD_test_ground_truth.json"

# 6. Check results in MCP_Stack/ground_truth_docs/eval_results_*.json
```
